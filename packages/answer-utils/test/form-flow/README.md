# Form flow tests

Exhaustive tests of the form pipeline: what a respondent can send, which question comes
next, what the logic rules compute, what the server stores and when a response is
discarded. They used to be a TLA+ model (`specs/form-flow`). Now every test runs the real
code over every answer map built from small value lists, so the checks can't drift away
from the code they describe. They run with each package's unit tests.

| Test                                             | Checks                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Was                                                                                                             |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `answer-utils/test/form-flow/submission.test.ts` | The server's route only moves forward and never visits an ending. Answers are exactly the route's questions, once each, with their field's kind. Every stored value has its kind's type (numbers numeric, ratings whole and in range). Required questions are answered. Choices stay within the options. Variables keep their type. A malformed answer is a `ValidateError`, never a crash. Open gap: an unanswered optional question is stored as `""`. | `Flow_*`, `Answer_*`, `Var_*` (`MCFlow`, `MCAttack`, `MCStrict`, `MCTypeHole`)                                  |
| `answer-utils/test/form-flow/logic.test.ts`      | Jumps go forward to fields that exist. Every rule can fire for some answer. Calculate rules change their variable. Branching questions cover every answer. A broken form is reported.                                                                                                                                                                                                                                                                    | `Config_*` (`MCBroken`, `MCBrokenRule`)                                                                         |
| `form-renderer/test/form-flow.test.ts`           | A respondent walking the form through the real store reducer sees exactly the route the server replays. The renderer and `isSubmissionDiscarded` agree on discarding: the server never drops a response the renderer saved, and the renderer never drops one the server would keep. The resolved ending can always be shown. A mutation check proves the agreement test catches the list #387 shipped with.                                              | `Client_MatchesServer`, `Termination`, `NoDataLoss`, `EndingsAgree`, `ShownIsResolved` (`MCTerm`, `MCDiscard*`) |
| `server/test/form-flow-outcomes.test.ts`         | Runs `completeSubmission` for every answer map, partial or complete, in time, at the time limit and too late. A discarded response has no side effects (no storage, IP count, queue or payment) and was valid. A stored one is never on a discarding route and is counted once against the IP limit. Once the time is up, the time limit's own submission stores exactly the valid answers it could reach. Nothing is accepted after the grace window.   | `DiscardedIsValidated`, `ShownSavingWhenSaved`, `CountdownIsAccepted` (`MCCountdownRejected`)                   |
| `webapp/test/form-flow-drift.test.tsx`           | After a kind change, the table renders an answer only under its own kind, and the guard is load-bearing. Open gaps: the builder keeps rules the new kind can't evaluate, and calculate rules that stop updating.                                                                                                                                                                                                                                         | `Drift_*` (`MCDrift`, `MCDriftUnguarded`, `MCDriftLogic`, `MCDriftCalc`)                                        |

The forms live in `fixtures.ts`. The server keeps its own copy, because its build compiles
`test/` and can't import from another package. To test another form, add it there with a
value list per question, then call the same checks.
